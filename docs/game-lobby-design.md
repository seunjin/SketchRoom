# 게임 로비 디자인 가이드

이 문서는 SketchRoom의 홈, 로비, 대기방 UI가 유지해야 할 디자인 방향을 정의한다. 현재 목표는 완성된 게임 캔버스가 아니라, 플레이어가 방을 만들고 들어가기 전까지의 캐주얼한 파티 게임 대기 경험이다.

## 디자인 방향

- **드로잉 파티 게임**처럼 보여야 한다. 업무용 대시보드, 관리자 콘솔, SaaS 카드 레이아웃처럼 보이면 안 된다.
- 화면은 가볍고 즉각적이어야 한다. 사용자는 방을 고르고 들어가는 데 필요한 정보만 본다.
- 캐릭터는 주인공이 아니라 보조 신호다. 큰 오리, 큰 마스코트, 확대된 얼굴형 캐릭터는 웃기게 보일 수 있으므로 피한다.
- 방 카드는 작은 게임 대기방 표지처럼 보인다. 제목, 공개 상태, 플레이어 슬롯, 입장 상태가 빠르게 읽혀야 한다.
- 새 방 만들기는 별도 모달 흐름으로 유지한다. 방 목록 그리드 안에 생성 카드를 섞지 않는다.
- Dialog와 Toast는 Woon UI를 사용한다. Woon은 오버레이, 포커스, 스크롤 잠금, 알림 런타임만 맡기고 시각 스타일은 SketchRoom이 소유한다.

## 시각 톤

- 밝은 종이색 배경과 얇은 격자/점 패턴을 사용해 스케치북 느낌을 만든다.
- 팔레트는 노랑, 민트, 보라, 코랄을 함께 사용한다. 한 가지 색 계열로만 밀지 않는다.
- 선은 조금 두껍게, 그림자는 짧고 단단하게 둔다. 장식적인 글로우나 그라데이션 배경은 사용하지 않는다.
- 모서리는 작게 둥글게 처리한다. 카드, 버튼, 모달은 `rounded-md` 수준을 기본으로 한다.
- 폰트는 굵고 또렷하게 사용하되, 카드 내부 텍스트는 과하게 크게 만들지 않는다.

## 홈 화면

홈은 로비로 들어가기 위한 플레이어 카드 생성 화면이다.

- 핵심 요소는 로고, 닉네임 입력, 현재 플레이어 카드, 대기방 입장 CTA다.
- 설명형 마케팅 문구, 기능 소개 카드, 지표형 대시보드 블록은 넣지 않는다.
- 플레이어 미리보기 카드는 분위기만 만든다. 실제 기능보다 크게 보이거나 화면을 압도하면 줄인다.
- 모바일에서는 입력 카드가 먼저 조작하기 쉽고, 텍스트가 버튼 안에서 줄바꿈 없이 읽혀야 한다.

## 로비 화면

로비는 방 카드 그리드가 중심이다.

- 상단에는 게임 타이틀, 현재 플레이어 카드, 새로고침, 방 만들기만 둔다.
- 본문은 방 카드 그리드만 사용한다.
- 방 ID, 생성일, 수정일, 버전, 내부 메타 정보는 기본 화면에 노출하지 않는다.
- 방 상세 패널을 별도로 열지 않는다. 카드 자체에서 입장 가능 여부와 현재 상태를 보여준다.
- 상세 정보가 필요하면 카드 안의 보조 정보 버튼으로 모달을 연다. 기본 카드에는 상세 정보를 계속 노출하지 않는다.
- 사용자가 이미 참여 중이면 다른 방 입장과 방 만들기를 비활성화한다.
- 방 생성 또는 입장에 성공하면 해당 방의 대기방 화면으로 이동한다.

## 방 카드

방 카드는 최소 정보만 보여준다.

- 방 제목
- 비공개 잠금 아이콘
- 작은 호스트 표시
- 참가자 슬롯
- 입장, 코드 입력, 나가기 상태

참가자 표현은 작은 토큰 슬롯을 기본으로 한다. 슬롯은 색상, 이니셜, 왕관 아이콘 정도로 충분하다. 큰 캐릭터 얼굴이나 큰 동물형 마스코트를 카드마다 넣지 않는다.

방 카드의 슬롯은 4개 고정으로 보여준다. 슬롯은 참가자가 누구인지 자세히 설명하지 않고, 찼는지 비었는지와 내 자리/호스트 자리 정도만 구분한다. `1/4` 같은 숫자 표기는 카드에서 반복하지 않는다. 이름 목록은 기본 카드가 아니라 상세 모달에서만 제한적으로 보여준다.

공개/비공개는 카드에서 텍스트 뱃지로 쓰지 않는다. 비공개 방에만 우상단의 작은 잠금 아이콘을 표시하고, 공개 방은 별도 아이콘을 두지 않는다. 카드에서 `참가 가능`, `가득 참` 같은 별도 상태 뱃지도 쓰지 않는다. 빈 자리 여부는 4개 슬롯으로, 입장 가능 여부는 버튼 활성/비활성으로 판단하게 한다. 텍스트 설명은 상세 모달에서 제공한다.

카드 크기는 한눈에 여러 방을 비교할 수 있어야 한다. 데스크톱에서는 3-4열 그리드가 자연스럽고, 모바일에서는 1열 카드로 내려간다.

## 모달

모달은 짧은 작업만 처리한다.

- 방 만들기: 방 이름, 공개/비공개, 비공개 코드
- 비공개 방 입장: 코드 입력

모달 안에 방의 내부 ID, 생성 시간, 긴 설명, 고급 설정을 넣지 않는다. 이후 게임 설정이 추가되더라도 기본 모달과 고급 설정은 시각적으로 분리한다.

## 대기방 화면

대기방은 실제 게임 시작 직전의 플레이어 슬롯 화면이다.

- 방 제목, 비공개 잠금 아이콘, 방 상태, 참가자 슬롯, 현재 플레이어 액션만 보여준다.
- 참가자 슬롯은 4개 고정으로 표시하고, 호스트와 내 자리를 명확히 구분한다.
- 참가자 목록은 이름, 표시 코드, 호스트, 내 자리, 준비 상태 정도만 보여준다.
- 초대는 우선 링크 복사 UI까지만 제공한다. 온라인 유저 목록과 직접 초대 메시지는 WebSocket 기반 presence/invite 작업에서 다룬다.
- 준비 상태는 participant API의 `isReady` 값을 기준으로 표현하고 갱신한다.
- 게임 시작 버튼은 호스트에게만 보인다. 방이 대기 중이고, 참가자가 2명 이상이며, 비호스트 참가자가 모두 준비 완료일 때 활성화한다.
- 게임 시작에 성공하면 방 상태는 `PLAYING`으로 바뀌고 대기방은 진행 중 상태를 표시한다.

## 인터랙션

- 공개 방은 입장 버튼으로 바로 참여한다.
- 비공개 방은 코드 입력 모달을 연다.
- 내 방은 카드에서 명확히 표시하고 나가기 버튼을 제공한다.
- 생성, 입장, 나가기 성공 후 방 목록과 참가자 슬롯이 바로 갱신되어야 한다.
- 에러 메시지는 짧게 보여준다. 예: `비밀번호를 다시 확인해 주세요.`
- 온라인 플레이어, presence, 초대 기능은 이번 로비 UI 범위에 넣지 않는다. 이후 WebSocket 기반 presence/invite 기능에서 별도 설계한다.

## 금지 패턴

- 대시보드형 통계 카드
- 방 ID, 생성일, 버전 같은 내부 정보 노출
- 카드 안의 큰 마스코트 또는 큰 동물 캐릭터
- 카드마다 다른 장식이 과하게 들어간 일러스트 중심 UI
- 랜딩 페이지형 히어로와 기능 소개 섹션
- 보라/남색/베이지 등 한 색 계열로만 몰리는 팔레트
- 카드 안에 또 다른 카드가 중첩되는 레이아웃

## 구현 기준

- 공통 색상은 `apps/web/src/index.css`의 Tailwind theme token을 우선 사용한다.
- 로비 API 상태는 TanStack Query의 room, participant query를 통해 표현한다.
- 참가자 슬롯은 실제 participant API 결과를 기준으로 그린다.
- 새 UI 컴포넌트가 커지면 route 파일에서 분리하되, 현재 기능 경계는 `apps/web/src/features/room`을 따른다.

## QA 체크리스트

- 홈에서 닉네임 생성 후 로비로 이동할 수 있는가?
- 공개 방은 버튼 한 번으로 입장되는가?
- 비공개 방은 코드 모달이 열리고 잘못된 코드 에러가 보이는가?
- 참여 중일 때 다른 방 입장과 방 만들기가 막히는가?
- 나가기 후 카드 슬롯과 CTA가 갱신되는가?
- 데스크톱에서 여러 방이 그리드로 비교되는가?
- 모바일 폭에서 카드가 1열로 자연스럽게 쌓이는가?
- 카드가 과하게 크거나 캐릭터가 확대되어 보이지 않는가?
